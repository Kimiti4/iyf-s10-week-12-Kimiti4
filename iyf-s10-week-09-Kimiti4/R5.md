# 6. EXPLICIT RECONNAISSANCE EVIDENCE PROTOCOL

R5 reconnaissance is an **evidence-collection phase**, not a code-reading exercise.

Every material finding MUST be supported by reproducible evidence from the authoritative repository, runtime, browser, HTTP layer, configuration, or tests as appropriate.

A statement such as:

```text
"JWTs are stored in localStorage"
"logout does not revoke sessions"
"CSP permits unsafe-eval"
"refresh tokens do not exist"
"the WebSocket uses the old token path"
```

MUST NOT be reported solely from an assumed or partial source reading.

The agent MUST establish the claim using the strongest available evidence.

---

## 6.1 Evidence hierarchy

Use the following evidence hierarchy:

```text
E0 — Direct runtime/security observation
     Actual HTTP response, browser storage, cookie,
     runtime behavior, WebSocket behavior, or executed attack.

E1 — Executed test evidence
     Focused automated test, integration test, adversarial test,
     or reproducible command whose output directly establishes
     the claim.

E2 — Static source evidence
     Exact authoritative source location showing the behavior,
     with file/path and relevant line or symbol.

E3 — Configuration/dependency evidence
     package/config/environment/schema/deployment evidence
     establishing a security property or dependency.

E4 — Documentation/design evidence
     Documentation or comments describing intended behavior.

E5 — Inference
     Reasoned conclusion not directly demonstrated.

R5 closure decisions MUST NOT rely on E4/E5 alone.
P0-7 closure requires E0/E1 evidence for runtime security properties,
supported by E2/E3 where appropriate.
```

When evidence levels disagree, **runtime evidence takes precedence over intended design**.

## 6.14 Evidence sufficiency rule

A finding may be called **CONFIRMED** only when:

```text
the observed behavior is directly supported by evidence
AND
the evidence comes from the authoritative repository/runtime
AND
the observation is reproducible
AND
no contradictory runtime evidence exists.
```

A finding supported only by source inspection MUST be labelled:

```text
SOURCE-CONFIRMED
```

rather than runtime-confirmed.

A finding supported only by inference MUST be:

```text
UNVERIFIED
```

## 6.16 No evidence inflation

The agent MUST NOT:

* convert "probably" into "confirmed"
* convert source intent into runtime behavior
* claim a test passed without executing it
* claim a browser property without inspecting browser/runtime state
* claim a header property without inspecting the effective HTTP response
* claim logout revocation without replay testing
* claim token absence merely because one source file does not contain it
* claim CSP hardening without testing application functionality
* claim refresh-token security without examining rotation/revocation behavior

If evidence cannot be obtained:

```text
REPORT:
UNVERIFIED
```

and explain exactly why.

## 6.18 Governing evidence principle

The governing rule for R5 reconnaissance is:

> **No claim without evidence; no runtime claim without runtime evidence; no closure claim without adversarial evidence.**

The objective is not to produce the most convincing report.

The objective is to produce a report that another engineer can independently audit and reproduce.
